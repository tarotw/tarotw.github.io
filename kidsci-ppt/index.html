第一幕 · 為什麼不能直接用現成流程

繁體中文不只是換一個語言標籤

直接套用英文或簡中的 AI 流程，會多出四種工作

字形
发 → 發／髮

簡轉繁是一對多，「頭发」要變「頭髮」，不是「頭發」

用語
激光 → 雷射
軟件 → 軟體

科學名詞要用臺灣課本的說法

讀音
企業 qì
垃圾 lè sè

臺灣華語和大陸普通話的讀音不同，合成語音常常念錯

兒童理解
寫的 ≠ 聽的

書面說明要改成小朋友聽得懂的對話，而且只能用耳朵聽

這是論文的核心要求之一：繁中是系統需求，不是翻譯後處理。「垃圾」在臺灣日常常念 lè sè，教育部字典兩種都收；重點是合成語音的選擇要符合我們選定的參考標準。

第二幕 · 五環全景 [1]

五環：一層包一層的 AI 工程

① Prompt
單位：一次輸入

要 AI 做什麼？

把角色、指示、範例、格式，組成一個輸入

🍽 寫好食譜

② Context
單位：一個視窗

讓它看哪些資料？

在預算內挑選、壓縮、丟棄：決定什麼上桌

🍽 只把要用的食材放上桌

③ Harness
單位：一趟

動手做，做對了嗎？

收集 → 動手 → 驗收：模型第一次動手、第一次被獨立判定

🍽 開火煮，再試一口味道

④ Loop
單位：一次執行

沒過就重來，何時停？

一趟接一趟，事先定好成功條件與煞車

🍽 不好吃就調整再煮，最多三次

⑤ Graph
單位：一次圖執行

誰做哪一段，誰簽核？

很多節點分工、共享狀態，放進審核與人工核准

🍽 整間廚房分工，主廚出菜前把關

內兩環是 Harness 要收集的材料；外兩環決定它跑幾次、怎麼協調、誰來核准。

📄 發表的論文 [1]Y.-K. Huang, “The five concentric rings of large-language-model systems engineering: A harness-centered tutorial from prompts to topologies,” ResearchGate preprint, 2026, doi: 10.13140/RG.2.2.35069.93920.
這是整個理論的全景。五環的名字來自業界的寫作，論文的貢獻是用「工作單位」把它們定義清楚：一次輸入、一個視窗、一趟、一次執行、一次圖執行。每一環也可以想成做事時要回答的一個問題：要 AI 做什麼、讓它看哪些資料、動手做對了沒、沒過怎麼重來與何時停、誰做哪段誰簽核。用煮菜來想：寫食譜、備料、開火試味道、調整再煮、整間廚房分工。中間那一環 harness 畫得最粗，因為論文以它為中心：內兩環是它要收集的東西，外兩環決定它跑幾次、怎麼協調和核准。這是「組件」關係，內環在外環裡面會跑很多次；圓的大小只代表誰包誰。節目裡每一環怎麼做，下一頁對照。
第二幕 · 五層各自的回頭路

每一層都有自己的回頭路，也都把上一層包進來

模型是大家都買得到的零件；包在它外面的一圈又一圈，才是工程。

圖改繪自 DailyDoseofDS.com〈Prompt / Context / Harness / Loop / Graph Engineering〉
上一頁講每一環是什麼，這一頁講每一環出錯時往哪裡回頭。由上往下看：Prompt 的回頭路最短，回應不好就改最弱的那一樣材料。Context 的回頭路是把這一步的輸出放回材料，下一步才看得到。Harness 驗收沒過，不是叫模型再說一次，而是重新收集，把失敗當成新的證據。Loop 決定要不要再跑一趟，靠的是事先講好的成功條件和煞車。Graph 的審核節點換一個模型、用乾淨的視窗，退回時重新分派給對的節點。再看有顏色的小方塊：每一層都把上一層當成一個框包進來，收集裡面是 Prompt 和 Context，Loop 裡面是一趟 Harness，Graph 的節點就是一個個 Loop。下一頁把 Harness 這一趟放大來看。
第二幕 · 以 Harness 為中心 [1]

一趟 harness：收集、動手、驗收

在《科學好好聽》裡，五環各做什麼：

① Prompt

請 AI 當科普作家，寫成小學生聽得懂的稿

② Context

只放查核過的文章、主持人設定、讀音標注

③ Harness

AI 上網查證文章，疑點列成清單

④ Loop

聽到錯字就修，再聽一次；修太多就整集重做

⑤ Graph

人耳通過，才產生測驗、詞彙、知識卡

📄 發表的論文 [1]Y.-K. Huang, “The five concentric rings of large-language-model systems engineering: A harness-centered tutorial from prompts to topologies,” ResearchGate preprint, 2026, doi: 10.13140/RG.2.2.35069.93920.
這頁是論文的核心：一趟 harness 由三步組成，收集、動手、驗收。收集這一步裡面包著前兩環：先在預算內挑選要上桌的東西，再組裝成一個輸入。模型輸出之後，動手：呼叫工具或子代理。這裡是安全邊界真正被打破的地方，因為文字變成了行動。然後驗收，要回傳判定和證據。不通過就重試，但重試不是重擲骰子，而是重新收集：把失敗寫回桌上，下一趟才看得到。通過就寫回狀態，由外面的 Loop 決定要不要再跑；Loop 外面再包 Graph，負責分工、審核和人工核准。下面一排是《科學好好聽》裡五環各自對應的步驟：寫稿、餵查核過的素材、上網查證列疑點、聽到錯字修完再聽、人耳通過才產生衍生教材。後面講 Pro 模式時，會一直回到這張圖。
第二幕 · 套疊之後的三條工作假設 [1]

三條工作假設

H1

外環能增加控制面，但修不好內環的缺陷

加一個審稿節點去抓格式錯，不等於把指令寫清楚。換更大的鍋子，救不了壞掉的食材。

H2

內環缺陷在外面每個工作單位都會重複出現

一個念錯的字，會被抄進測驗、詞彙卡、短影片字幕。所以先往內修，省得最多。

H3

每一環都需要和工作單位相符的評估工具

一句寫得好，不代表整集合格；整集合格，不代表查得到是誰批准的。

📄 發表的論文 [1]Y.-K. Huang, “The five concentric rings of large-language-model systems engineering: A harness-centered tutorial from prompts to topologies,” ResearchGate preprint, 2026, doi: 10.13140/RG.2.2.35069.93920.
把五環當成組件關係之後，論文提出三條工作假設。它們是分析的指引，不是定理，論文也寫了各自在什麼條件下會失效。H1：外環能增加控制面，但修不好內環的缺陷。例外是外環其實在重寫內環的產物，那就算是內環的工程。H2：內環缺陷會在外面每一個工作單位重複出現。注意是重複，不是放大。乘數來自成本模型：一次圖執行的成本大約是節點數乘迭代數乘每次迭代的趟數，再乘每次呼叫的成本；一個每次呼叫多花 δ 的缺陷，每次圖執行大約多花 f·m·r·δ。這個近似假設各因子獨立。如果有驗收把有缺陷的結果都擋下來，缺陷不會往外傳，但產生它的成本還是一再重複。H3：每一環都需要和工作單位相符的評估工具。對我們特別重要的是 H2：審核要放在衍生教材產生之前。

Auto 模式 · 一個關鍵的設計決策

為什麼不自己寫逐字稿再 TTS？

A　逐字稿＋TTSB　NotebookLM
自然度念稿感附和、搶話、停頓，孩子聽了停不下來
控制每個字都可控黑盒，每次結果不同

我們用控制權換到了自然度和自主性，所以要在外圈補上修音和把關。

講到動物叫聲為什麼這麼大，主持人突然搬出東北方言梗演起吵架：
「你瞅啥？」（你看什麼？）「瞅你咋地！」（看你又怎樣！）
這種梗我們寫不出來，卻讓「叫聲是為了宣示、對峙」一聽就記住。

直接播放，最後兩秒是重點。「你瞅啥？瞅你咋地！」是中國東北的方言梗，模仿兩人在路上瞪眼挑釁準備吵架。主持人把動物大聲吼叫，比喻成人類互相嗆聲。這就是選 NotebookLM 的理由：它的自主性會創造出人類編劇想不到的效果。但同一份自主性，也會產生前面的「屎」。所以要靠人耳決定：哪些驚喜留下，哪些事故剪掉。
選擇的代價

Pro 模式 · 全景

三條線：文字、聲音、把關

文字線先把劇本寫到過審；聲音線把劇本和音效表一次組裝；把關線是機器量測加人耳。每個節點都產出一個有版本的檔案，所以錯在哪裡，就只重做那一段。人耳試聽沒過，有兩條回頭路：音效放錯，回到音效那一段重做；念錯字，回到分段 TTS，只重新合成那一段語音。粉紅實心的節點是人耳，它在流程裡是必經節點。接下來就照這三條線走：先文字線，再聲音線，最後把關線。
文字線 · ① Prompt ＋ ② Context

文字線：先寫對，再念對

寫對

劇本是一份契約

每一句只有三件事：誰說、怎麼說、說什麼。

{ 誰說   "小博",
  怎麼說 "臺灣腔・興奮的現場報導・重音放在漆黑無光",
  說什麼 "這裡終年漆黑無光，只能靠探照燈照亮。" }

「說什麼」會被一字不差念出來，稿上不能有任何不打算念的字。A1 有 122 句，用了 121 種不同的演法。

念對

讀音和口音，要在生成前處理

語音模型念不好的字，先改寫成念得對的同音字：好奇 → 浩奇、科學好好聽 → 科學豪好聽。

一句演法寫錯，主持人就變成北京播音腔。這種錯修在工具的預設，而不是只修這一集。

錯在文字線，聲音線就得整批重來。所以文字要先過關。

文字線處理兩件事。第一，寫對：劇本每一句只有誰說、怎麼說、說什麼三個欄位，「說什麼」會被逐字念出來，所以稿子本身要乾淨。第二，念對：模型念不好的字，在生成前先改寫；口音也要在生成前就指定好。接下來兩頁各講一個真實例子：審稿怎麼擋錯，讀音怎麼修。

聲音線 · ③ Harness · 一次合成請求

從劇本到聲音：一次合成請求長什麼樣

一次請求就是一批句子。每句帶著劇本契約的三個欄位：講者決定用哪個聲線，text 逐字念出，style 只管怎麼演。服務回傳一段聲音。

一集有一百多句，而服務一次最多兩位講者，所以要把劇本切成好幾批、每批一個請求，再把所有批的聲音接回一集。接下來的問題是：在哪裡切？

先把機制講清楚。劇本每一句有講者、style、text 三個欄位，就是文字線那一頁的劇本契約。送給 Gemini 3.8 TTS 的請求，內容是模型名稱、輸出格式、兩位講者各用哪個聲線，以及一串句子。服務照 text 逐字念、照 style 演，回傳一段 WAV 聲音和用量。中間這三句是 A1 的真實台詞，style 原文是英文，前面都有一段固定的口音錨點。因為一次最多兩位講者，一集一百多句又不能一次送，所以要切成批。
聲音線 · ③ Harness · 切批

一整集不能一次送：切在哪裡，決定自然不自然

劇本 122 句→切成好幾批→每批送一次→一段聲音→接回一集

上一頁說過：一集要切成好幾批分別合成，再接回來。每批多長是取捨；真正的難題是切在哪裡。

難在切點：同一批的句子一起合成，語氣能互相呼應；切到兩批，回答聽起來就像突然開了新話題。問句和回答、沒說完的話、短短的搭腔，都不能被切開。

上一頁講了為什麼要切，這頁講難在哪：切點會影響語氣。右邊是 A1 的五句真實台詞，只有最後一個地方可以切。會話分析把問與答叫做相鄰對，短短的回應叫搭腔，這些都不能拆開。我們在 46 集裡數過，大約四成的句間邊界都不能切。
聲音線 · ③ Harness · 接縫

接縫：讓兩批之間聽起來像換一口氣

每批的回應是一段 WAV，頭尾都帶一段長短不一的靜音。直接相接，接縫處的空白會忽長忽短。我們先修到只剩 20／30 毫秒，再統一補 120 毫秒：接縫約 170 毫秒，落在人類對話換人說話的常見範圍裡。

每個接點另做 5 毫秒的淡入淡出，避免波形突然斷掉產生「喀」聲。這些都是訊號層的小事，但聽眾一定聽得出來。

文獻：Stivers et al. (2009), PNAS 106(26)；Levinson & Torreira (2015), Frontiers in Psychology 6:731
左邊是接縫的時間設計。合成回來每一批頭尾都有長短不一的靜音，修掉之後補固定的 120 毫秒，加上保留的 20 和 30 毫秒，接縫大約 170 毫秒。心理語言學的研究發現，人類對話換人說話的間隙通常在 200 毫秒上下；Stivers 等人比較十種語言，都避免重疊、也避免長沉默。170 毫秒落在這個範圍裡，聽起來像換一口氣。右邊是聲音檔的結構：檔頭加樣本。直接把檔案接起來，第二個檔頭會被當成聲音播出。格式不一致更糟，24 kHz 被當 48 kHz 播，速度兩倍、音高高八度。
聲音線 · ⑤ Graph · 音效對時間

音效要對準時間：輪流，或同時

beat：位置在組裝時就決定了，不用猜。

overlay：要從合成好的聲音裡，找出那幾個字在第幾秒。

難在中文：同音字、異體字太多。1,614 個對齊點裡，有 11% 辨識出來的字和劇本不一樣（牠→他、台→臺），念對了，寫法卻不同。

原則：對不上就停下來請人看，絕不猜一個秒數。笑點蓋錯句子，孩子一定聽得出來。

46 集故事模式：531 個 beat、1,614 個 overlay

故事模式的音效有兩種。beat 是對話停下來讓音效播完，它的位置在組裝時就算好了。overlay 是壓在某幾個字上的短音效，要先知道那幾個字是第幾秒說的，這要從合成好的聲音裡推論。中文的同音字和異體字讓這件事變難：我們的資料裡有一成多辨識結果和劇本寫法不同。所以規則是對不上就停，不猜，寧可請人看一眼。
